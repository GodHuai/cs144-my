# QUIC UDP Transport Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Carry existing protected QUIC TLS flights over real IPv4 and IPv6 loopback UDP, preserving ECN and datagram boundaries.

**Architecture:** Add a Linux QUIC-specific nonblocking RAII socket and numeric dual-family endpoint, leaving the existing IPv4 TCP/UDP utility intact. A bounded integration harness composes this production I/O with existing TLS, Initial and Handshake packet protection, and 1-RTT frames. Connection dispatch, stream semantics and recovery remain separate future milestones.

**Tech Stack:** C++20, Linux recvmsg/sendmsg, OpenSSL 3.5.9, CMake/CTest, ASan/UBSan.

**Spec:** docs/quic-v1/design.md (UDP I/O and loopback validation).

## Global Constraints

- QUIC v1; TLS 1.3 uses the existing external QUIC TLS adapter.
- IPv4 and IPv6; ECN is extracted from IP_TOS / IPV6_TCLASS.
- No system dependency changes, no privileged ports, no secrets in logs.
- Work in the existing isolated branch; preserve unrelated TCP test failures.
- This milestone supplies I/O and a test harness, not a production connection state machine or reliable stream API.

## Review Focus

- Datagram truncation must never expose a partial QUIC packet: discard and throw length_error; test a subsequent full datagram.
- Empty datagrams differ from EAGAIN: test both explicitly.
- Descriptor ownership and construction failure must not leak: RAII, deleted copying, CLOEXEC/nonblocking flags; inspect construction paths.
- IPv6 must use its own traffic-class ancillary format and retain scope IDs: test all ECN values on both families and numeric scope roundtrip.
- Invalid endpoint, family, ECN and oversize payload must fail before send: test no unexpected peer datagram.
