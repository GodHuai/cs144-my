# QUIC v1 受保护包头布局设计

本轮为 RFC 9000 v1 Initial、0-RTT、Handshake 与 1-RTT 包提供包头构造和包边界解析。解析的输入是 UDP 数据报中的字节串。长包头从版本、两个连接 ID、Initial Token、Length 计算包号字段起点和包的终点；短包头使用调用方已知的目的连接 ID 长度，且占据数据报剩余部分。解码结果保留字段和偏移，供 RFC 9001 的报头保护、AEAD 与包号恢复使用。

包号长度两位受报头保护，不能在解密前读取。因此布局解析器只读不受保护的字段，不读包号或受保护载荷，也不根据受保护的保留位判断错误。长包头 Length 包括包号字段和受保护载荷。布局解析器确保从包号字段起点起还有至少 20 字节，使报头保护的 `pn_offset + 4` 处可以取满 16 字节样本。此条件也是未来加密构造器的约束。

编码器生成未保护的包头和截断包号，供未来 AEAD 以整个未保护包头为 associated data；随后才能对完成的密文包施加报头保护。长、短包头构造器都接收预期的密文加 AEAD tag 长度，以拒绝无法取到报头保护样本的包。版本协商和 Retry 包格式不同，留给独立解析与完整性校验模块。本模块遇到它们或未知版本明确拒绝；连接层不能把拒绝误判为协议错误响应。

规范依据：[RFC 9000 §17.2](https://www.rfc-editor.org/rfc/rfc9000.html#section-17.2)、[§17.3.1](https://www.rfc-editor.org/rfc/rfc9000.html#section-17.3.1)、[RFC 9001 §5.4](https://www.rfc-editor.org/rfc/rfc9001.html#section-5.4)。
