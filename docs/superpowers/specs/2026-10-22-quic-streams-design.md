# Reliable application streams and flow control

## Observable behavior

Expose open_stream(unidirectional), write_stream(id,data,fin), read_stream(id,max_bytes), stream_ids(), reset_stream(id,error), stop_sending(id,error), stream_send_buffered(). APIs are available only after TLS completion. Read returns data, eof and optional peer reset error. Stream IDs distinguish initiator and direction; peer higher IDs implicitly open lower IDs without allocating every placeholder. Reject illegal directions/unopened local streams (STREAM_STATE_ERROR), excess peer stream ordinal (STREAM_LIMIT_ERROR), flow-limit excess (FLOW_CONTROL_ERROR), conflicting final sizes (FINAL_SIZE_ERROR), offset overflow (FRAME_ENCODING_ERROR).

ApplicationStreams owns independent send/receive state. Support ordered delivery under reordering, duplicates, overlapping frames, FIN before missing data, zero-length FIN and reset accounting. Retain accepted bytes until application consumes them. Track receive connection credit by per-stream highest offset/final size, not novel data length. Consumption and RESET release receive credit; monotonic MAX_DATA/MAX_STREAM_DATA updates are reliable. STREAM retransmission never consumes new flow credit. FIN/RESET final size remains immutable. STOP_SENDING requests a reliable RESET of the sender's committed final offset; accepted unsent suffix is cancelled; committed bytes remain charged to send admission until ACK even after RESET.

Local transport parameters 0x04..0x09 govern credits; omitted means zero, no new defaults. Receive window and each per-stream window are bounded to 1 MiB, offered stream counts to 128 per direction; validate before handshake. Send buffer bounded 1 MiB across connection, including unacknowledged data. At most 128 locally opened streams per direction during this milestone; stream metadata retained as tombstones, no MAX_STREAMS replenishment yet. Thus finite stream lifetime count is an explicit limit. Peer MAX_STREAMS accepted monotonically up to 2^60, local open may backpressure at own resource bound. Receive sparse ranges are merged and bounded by advertised remaining credit. Send byte ranges freed on ACK, including out-of-order/late ACK of any logical copy. FIN-only writes carry no flow bytes; peer-reset reads expose error and release gaps' final-size credit. Do not support 0-RTT or change crypto buffers.

## Scheduling and integration

ApplicationStreams::pending() peeks control or <=600-byte fresh STREAM, sent(frame) commits only at datagram handoff, acknowledged(frame) frees send storage. Coalesce unsent MAX/BLOCKED control updates by frame type/id; retransmit committed controls through existing shared RecoveryData. Round-robin fresh streams. Retransmissions may continue for already committed bytes after RESET; they remain within final size and do not reopen stream or add flow credit. PacketRecovery acknowledged gains an optional callback invoked exactly once per newly delivered logical frame; physical flight accounting remains independent. Packet preflight stages stream changes on a copy and commits only after every supported frame passes, before ACK generation; no partially retained packet can be acknowledged. Terminal connection clears application state. Exact wire-size, cwnd/pacing/anti-amplification gates remain before PN/cursor commitment.

## Validation and boundaries

Unit tests: client/server bidi/uni directions and implicit opens, reordered/duplicate bytes and FIN gaps, final size errors incl RESET vs highest offset, sparse high offsets charge aggregate limits, all-or-nothing packet receive, default-zero limits, dynamic MAX updates (including lost updates), retransmit credit, ACK buffer reclamation, bounded admission, reset/stop and monotonic limits. Connection tests: TLS then real protected bidirectional and unidirectional data; deterministic loss/reordering/ACK loss; tiny windows stall until read produces reliable credit; FIN and cancellation. Existing QUIC and full CTest run with 30-second timeout; report known baseline failures by name. Independent review before branch commit, update project docs and local notes. Remaining: stream-count replenishment/cleanup, prioritization beyond round-robin, lifecycle/close timers, persistent congestion/ECN, migration/security/session work and external interop. This is a bounded stream milestone, not full QUIC conformance.

Reference: RFC 9000 sections 2–4, 19.4–19.14, 18.2 (https://www.rfc-editor.org/rfc/rfc9000.html). Protocol details should be checked against these sections, not inferred from existing codec tests.
