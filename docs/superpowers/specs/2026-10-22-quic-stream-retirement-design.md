# QUIC stream retirement and replenishment

Continue authorized implementation on ubuntu-vm /home/huai/minnow-quic-proposal, branch quic-v1-proposal, base 35b76c5. Keep existing C++20/OpenSSL/NewReno/pacer. No lifecycle timers/listener work in this milestone.

Close a stream only when every present half is terminal: send FIN acknowledged with no unacknowledged prefix, or RESET acknowledged; receive EOF or RESET observed by application via read. A uni stream has only its legal half; bidi requires both. Receive-observed state remains monotonic across late RESET while a bidi send half stays live. read returns the final result before state is removed. Thereafter stream_ids lists live materialized state only; reads of retired IDs return empty/non-EOF, writes/reset/stop fail. Apps retain final results if needed. Unread bytes or an unobserved reset cannot be silently reclaimed.

Retire heavy Stream buffers/state and unsent per-stream controls. Store retired ordinal intervals separately for each of four stream types; merge adjacent intervals so metadata is bounded by outstanding stream gaps rather than lifetime count. Late valid frames on retired IDs are ignored, never recreate state, re-charge flow credit or replenish twice; wrong directions still error. Once retired final-size detail may be discarded (RFC 9000 section 4.5); documented late-frame policy.

On peer stream retirement increment the corresponding cumulative recv_counts by one up to 2^60, queue coalesced reliable MAX_STREAMS. Local retirement frees only local resource capacity, not peer-granted permission. Local open checks active count (opened minus retired), capped128 per direction, not cumulative opened>=128. Local/peer cumulative IDs never reused; check 2^60 ceiling before ID arithmetic. Initial local negotiated peer credit remains <=128 per direction. Implicit-open gaps occupy credit and remain represented by high-water counters until actual stream completion; retired intervals never absorb a live gap.

On logical RESET delivery, release that stream's remaining buffered committed payload and mark old STREAM RecoveryData canceled, but preserve physical flight until actual ACK/loss/discard. PacketRecovery performs cancellation after ACK range traversal before existing logical active cleanup, without reentrant record mutation. No callbacks for canceled STREAM payload. Pending obsolete copies are suppressed. Prior to RESET delivery, existing committed-byte admission bound remains enforced.
