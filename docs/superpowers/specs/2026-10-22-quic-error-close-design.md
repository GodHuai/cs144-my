# QUIC transport error and handshake close design

Continue user-authorized native implementation in isolated /home/huai/minnow-quic-proposal, branch quic-v1-proposal base b14b00b. Existing C++/OpenSSL sansIO pinnedpeer architecture. No permission gate or push/merge.

Goal: authenticated protocol/TLS failures produce transport CONNECTION_CLOSE rather than only silent Failed, and close before confirmation supplies every still-available Initial/Handshake/1RTT protection level the peer may have. Reuse previous bounded cached ciphertext Closing lifecycle, independent3x cap, antiamplification and fixed3PTO. Default timers/API unchanged.

Automatic protocol failure transitions Closing when a protected close can be constructed, retaining transport_error and full close_info; receive returns Failed both for triggering datagram and subsequent closing error traffic. App close still returns bool. Only unrecoverable local errors (clock regression, packet-number exhaustion, packet construction exception/no usable keys) use silent Failed. Peer close remains Draining. All application/recovery work is cleared before output. First diagnostic stays immutable.

When first Initial authenticates (including reserved-bit violation), store minimal peer SCID/originalDCID/Initial keys for error reply before semantic preflight; do not feed TLS/commit streams first. Do not bind unauthenticated layout. Normal TLS creation/bind remains after successful preflight. Errors name offending frame type when known; 0 means unknown, e.g. transactional application-stream error. TLS errors retain existing numeric0x100+alert or transport errors, no private diagnostic reason sent.

Connection caches two outgoing traffic-secret copies through optional TlsHandshake constructor WriteSecretObserver callback, invoked on each write secret synchronously inside yield_secret before TLS can fail/cleanse. TLS's secret() after failure still returns none and TLS cleanse remains unchanged. Observer must not reenter TLS, exceptions fail closed through existing callback containment. Cache wiped at each level retirement, terminal stop, destructor, including exceptional construction paths (RAII). No read secrets cached and no logging. TLS-only callers without observer unchanged.

Build one cached UDP datagram <=1200 bytes: Initial first, Handshake next, 1RTT last. Before confirmation include available nonretired Initial and cached Handshake/1RTT; after confirmation MUST only1RTT. Every constituent gets fresh PN in its own space. If any allocation exhausts, send nothing, silentFailed. Pad an Initial-containing datagram to exactly1200 by enlarging its Initial payload after accounting other protected packets. Do not resurrect retired levels. An application close in lower levels is converted to transport APPLICATION_ERROR0x0c, frame_type0 and EMPTY reason; 1RTT retains application code/reason. Local close_info retains original application diagnostic. Transport close error is same at all levels. No periodic retry: replay exact coalesced ciphertext only on attributed input under existing limiter.

Tests: first authenticated Initial malformed/ACK/reserved error close decryptable and correct code/CIDs; damaged AEAD silent; first Initial peerclose remains silent. Established client close before sending Finished: lower Handshake close allows Handshaking server drain; retained app reason absent lowerlevel. Server has Handshake write key before sending ServerHello but client only Initial: induce unsupported authenticated Initial frame, verify coalesced Initial+Handshake(+1RTT if key generated) closure and decryptInitial; drop lowerlevel and verify key-aware peer path where useful. Client cert/SNI rejection in same TLS advance that learned Handshake keys =>correct protected close, no secret() regression. Confirmed app/protocol failures only1RTT. Existing lifecycle and prior seven baseline full failures unchanged. No stateless reset/listener/keyupdate implementation.
