# QUIC connection lifecycle design

Continue the pinned-peer sans-I/O C++/OpenSSL engine on branch quic-v1-proposal, base aa63e44. User requests continued implementation; native inline execution and existing isolated VM worktree are retained.

Add application close after TLS completion: bool close(uint64_t application_error=0, std::string_view reason={}). Reject error beyond max_varint or reason beyond256bytes without changing connection. Queue exactly one cached protected 1-RTT CONNECTION_CLOSE packet with a fresh PN. Closing immediately disables application work and discards TLS/streams/recovery; only cached wire, route identity, reason and expiry remain. No new packets are constructed in closing. Close datagrams are congestion/pacing exempt, but obey existing anti-amplification AND an independent three-times-attributed-received cap, seeded with pre-close received traffic and charging every close handoff because incoming keys are discarded. Pinned wrong address/CID does not elicit responses. A response to attributed incoming traffic can be queued after one PTO, then exponential intervals, never beyond original3PTO expiry; repeated polls and timer expiry do not spontaneously resend. Retrying exact cached wire is RFC9000 10.2.1 permitted. No transition closing->draining inspection because incoming keys are discarded (optional in RFC).

Peer CONNECTION_CLOSE captures full frame into close_info(), enters silent Draining, frees TLS/streams/recovery, expires after3PTO then Closed. No echo. Both timer types integrate into next_timeout_us/on_timeout even when amplification blocks sending. Closed has no deadline/output/app work. ConnectionState adds Closing and Closed. Existing Failed stays a silent local abort (including handshake/protocol errors); automatic error close, stateless reset, key update and listener/dispatcher tombstones are explicitly subsequent work.

Idle timeout from transport parameter0x01 in milliseconds: minimum nonzero local/peer, zero+zero disabled; use local value before peer parameters. Start from engine construction, reset on authenticated successfully processed packet, and on only the first actual ack-eliciting packet handoff since that receive. Discarded/forged/foreign packets, ACK-only handoff, queueing work and repeated sends cannot keep connection alive. Duplicate authenticated packet numbers do not reset idle (avoid captured ciphertext replay retaining state). Deadline = last activity + max(negotiated interval,3 current base PTO); compute from current RTT (no recovery exponential backoff), saturating integer arithmetic. Deadline shrink after negotiation is allowed. Silent idle expiry frees resources ->Closed. APIs receive/poll/close also enforce expiry so an omitted callback cannot revive expired state. Defaults remain disabled for compatibility. PTO uses Application with max_ack_delay only when confirmed, otherwise Handshake estimate, with 999ms initial. No handshake-duration deadline if idle disabled.

Test dedicated quic_connection_lifecycle binary: protected peer close info and expiry; dropped first close plus bounded exact-wire resend; wrong peer/CID and cap; stream/recovery disposal; negotiation/nonzero rules; idle reset on receive/one handoff, repeated sends/ACK-only and forged duplicate distinctions; idle floor3PTO; saturation; expiry at boundary. Existing QUIC suite and full known-baseline failures must remain unchanged.

Reference: RFC9000 sections10.1,10.2.1,10.2.2. Implementation choices (256byte reason bound, no closing decrypt, application-only API) are agent defaults within continued implementation scope.
