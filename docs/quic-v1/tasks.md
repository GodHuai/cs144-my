# QUIC v1 实施与验收任务

以下是提案阶段的执行顺序。每项完成后保存对应测试证据；实现阶段可细分为代码提交。任何会改变外部行为或支持范围的决定先更新行为要求与设计。

1. [ ] **构建与 TLS 技术探针**：建立 `quic/` CMake 目标；验证可用的 TLS 库、QUIC 回调、证书和密钥导出；固定版本及构建步骤。验收：最小探针在虚拟机上可复现。
2. [ ] **线格式与解析**：实现变长整数、包头、包号恢复、帧编解码及错误路径。验收：RFC 示例/向量和畸形输入测试通过。
3. [ ] **安全握手**：实现 Initial、Handshake、1-RTT 密钥与包保护、CRYPTO 帧、传输参数及双端 TLS 1.3 握手。验收：loopback 成功握手；错误证书、错误认证标签和非法状态被拒绝。
4. [ ] **单流与连接生命周期**：实现客户端/服务端 API、STREAM 发送接收、FIN、关闭与超时。验收：多段乱序与重复数据仍交付一致的字节流。
5. [ ] **ACK 和恢复**：实现 ACK 区间、RTT、丢包判定、PTO、重发信息调度和初始拥塞控制。验收：注入丢包、延迟、重复、乱序时仍可靠完成，且包号不复用。
6. [ ] **多流与流量控制**：每流状态、并发限制、MAX_DATA/MAX_STREAM_DATA 更新、final size 与 RESET/STOP_SENDING。验收：两个流独立前进；额度和最终长度违规被拒绝。
7. [ ] **协议边界与互通**：检查地址验证、反放大、版本/Retry、连接 ID、密钥更新和错误关闭；与至少一种独立 QUIC v1 实现互通。验收：记录具体对端版本、运行命令、握手/流/关闭结果与失败项。
8. [ ] **回归与详细讲解文档**：运行现有 Minnow TCP 测试和 QUIC 测试；编写 `docs/quic-v1/implementation.md`，逐项对照 RFC 9000/9001/9002 与实际源码，解释关键数据结构、状态机、收发路径、测试证据、支持矩阵及已知限制。文档只在实现和测试结果可核验后完成。

## 提案评审点

- 确认首轮目标为 QUIC v1 可互通的最小实现，且客户端与服务端均由本项目提供。
- 确认 TLS 库探针结果后锁定库与版本；未完成此项之前不承诺握手实现细节。
- 明确选定外部互通对端及证书配置，避免将自测当成协议互通证据。
